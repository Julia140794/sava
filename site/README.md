# SAVA est.2026

Адаптивный сайт бьюти-студии в Минске: косметический массаж лица, маникюр и педикюр.

## Локальный запуск

Требуется Node.js 24, npm 11.

```bash
cd /workspace/sava/site
npm_config_cache=/workspace/.npm-cache npm ci
npm run dev -- --hostname 0.0.0.0
```

Production-проверка:

```bash
npm run lint
npm run build
npm run start -- --hostname 0.0.0.0 --port 3000
```

Шрифт Manrope и изображения локальные; сборке не нужны Google Fonts или другие внешние CDN. `.env.example` содержит только названия настроек. Секреты положите в игнорируемый `.env.local` или настройки хостинга, не в чат/репозиторий.

## Приём заявок

Приём отключён по умолчанию. Пока не заданы SUPABASE_URL, SUPABASE_SECRET_KEY, TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID и LEAD_INTAKE_ENABLED=true, кнопка отправки неактивна; API возвращает 503 на валидную заявку, а не ложный успех.

1. Дополнить контакты и юридические сведения владельца, утвердить /privacy, сроки и условия обработки и передачи данных.
2. Создать таблицу через ../supabase/leads.sql. RLS включён, публичных политик нет.
3. Настроить Supabase и Telegram. Боту нужно отправить /start от получателя.
4. Задать SITE_URL (реальный абсолютный адрес) для canonical, sitemap и OG. Без него страницы помечены noindex, sitemap пуст; локальные OG URL не предназначены для публикации.
5. Только затем включить LEAD_INTAKE_ENABLED=true и пересобрать сайт: состояние кнопки определяется при сборке статической страницы.
6. Проверить реальную заявку в обоих каналах. Реальная доставка пока не проверена из-за отсутствующих настроек.

API валидирует имя, телефон, услугу, согласие и длины; ограничивает тело 16 КБ; отсекает honeypot и чужие Origin; содержит ограничение частоты в памяти процесса. На нескольких экземплярах оно не общее: до публичного трафика дополнить лимитом хостинга/WAF либо общим хранилищем. Логи доставки содержат только статические сообщения, не ключи и данные заявителя.

Доставка считается успешной при успехе хотя бы одного канала. Сбой второго отмечается в серверном логе. Обработчик пока не обеспечивает дедупликацию повторных отправок и повторную доставку — это отдельное улучшение перед большими объёмами.

## Публикация

Код сайта в site/, Root Directory при импорте в хостинг — site. Сайт ещё не опубликован. Подключить собственный репозиторий и коммерчески допустимый хостинг; Vercel Hobby не предназначен для сайта действующего бизнеса. Не отправлять сайт в upstream репозитория пакета агента.

Перед запуском заменить фактическими данными отсутствующие контакты, цены/длительности при желании, проверить политику, реальную доставку, домен и индексацию. Чек-лист — ../content/after-launch.md.

## Netlify — проект savae

Пользователь выбрал существующий проект https://app.netlify.com/projects/savae/ и сообщил, что добавил настройки в Netlify. Фактические значения и их доступность сборке из этой среды не проверены.

В корне репозитория находится netlify.toml: base=site, команда npm run build, publish=.next, Node.js 24, адаптер @netlify/plugin-nextjs. Это серверное Next.js-приложение: загрузка одной папки HTML или static export не подходят из-за API заявок.

Привязка: существующий проект Netlify → Project configuration → Build & deploy → Continuous deployment → Repository → Link repository → GitHub → Julia140794/sava → main. Если base уже задан в интерфейсе, сверить его с site из netlify.toml, не добавлять site дважды. Package directory при обычной структуре можно оставить пустым. Установить полный SITE_URL из фактического production domain Netlify (не URL панели app.netlify.com). После изменения переменных запустить новую production-сборку. Секреты должны быть доступны серверным Functions, а SITE_URL и LEAD_INTAKE_ENABLED также сборке.

Сохранение ключей в облачной среде Codex отдельно от переменных Netlify. Токены Netlify и API-ключи нельзя коммитить. Для прямого управления через API нужны отдельный доступ к аккаунту и API ID проекта; в текущей среде такого доступа пока нет. Сохранение netlify.toml само по себе не подтверждает привязку проекта или публикацию.
