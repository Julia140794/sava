# Подтверждение записи клиенту в Telegram

## Что подготовлено

Обычные заявки и уведомления владельцу работают как раньше, пока TELEGRAM_CONFIRMATIONS_ENABLED не включён. После включения клиент увидит кнопку Telegram после новой заявки. Привязка добровольная; без неё бот не может писать клиенту по номеру телефона.

## Первое включение — только владельцу

1. Откройте supabase/telegram-confirmations.sql в GitHub, скопируйте его целиком. В Supabase проекта SAVA: SQL Editor → New query → вставить → Run. Должен появиться Success. Старые leads не изменяются, добавляется закрытая таблица telegram_bookings.
2. Дождитесь публикации обновления Netlify. Откройте https://savae.netlify.app/telegram-setup.
3. Нажмите «Создать секрет», затем «Скопировать». Сохраните его у себя. В Netlify → Environment variables добавьте TELEGRAM_WEBHOOK_SECRET с этим значением. Не присылайте секрет в чат. Он должен быть доступен Functions и Builds в Production.
4. Добавьте TELEGRAM_CONFIRMATIONS_ENABLED=true, также для Functions и Builds в Production. Проверьте SITE_URL=https://savae.netlify.app. Существующие четыре настройки Supabase и Telegram оставьте.
5. Deploys → Trigger deploy → Deploy site. Дождитесь Published.
6. Вернитесь на /telegram-setup. Вставьте сохранённый секрет и нажмите «Подключить бота». Страница проверит таблицу и регистрацию обработчика. Токен BotFather вводить на странице не нужно — он уже в Netlify.

Регистрация заменяет webhook данного бота. Используйте отдельного бота SAVA; не подключайте его параллельно к другим сервисам или polling. Очередь Telegram намеренно не очищается.

## Как пользуется клиент

1. Оставляет новую заявку на сайте.
2. После успеха нажимает «Получить подтверждение в Telegram» и Start/Запустить у вашего бота.
3. Бот сообщает, что Telegram подключён, но время ещё не подтверждено.
4. После вашего подтверждения получает услугу, дату, время по Минску, адрес и телефон.

Кнопка доступна только для новых успешно сохранённых заявок. Ссылка на первоначальную привязку действует 24 часа. Не пересылайте её другим людям; первый клиентский аккаунт закрепляется за заявкой. Команда /stop отключает клиентские подтверждения. Свободные сообщения и ответы клиента пока не пересылаются владельцу, изменения записи согласовываются по телефону.

## Как работает владелец

1. В своём личном чате с ботом открывает уведомление о нужной заявке. После Start клиента бот также присылает сообщение с его именем, телефоном и ссылкой на выбор времени.
2. Нажимает «Выбрать время и подтвердить». Если клиент ещё не подключён, бот объяснит это.
3. Отвечает именно на сообщение-запрос датой в формате ДД.ММ.ГГГГ ЧЧ:ММ. Время по Минску; допускается только будущая дата. Ответить нужно в течение часа. При истечении срока ещё раз нажмите кнопку.
4. Проверяет клиента, услугу и время в предварительном сообщении. Кнопка «Изменить время» позволяет исправить ввод.
5. Нажимает «Подтвердить и отправить клиенту». Клиент получает подтверждение, владелец — сообщение о доставке.

Это ручное согласование, не календарь доступных слотов: владелец сам проверяет, что выбранное время свободно. Изменение уже отправленного подтверждения и напоминания пока не реализованы. Телефон студии остаётся каналом для переноса и отмены.

## Защита и сбои

Webhook защищён отдельным секретом Telegram; чужие запросы отклоняются до работы с базой. Действия владельца разрешены только личному TELEGRAM_CHAT_ID, одновременно проверяются пользователь и чат. Владелец в групповом чате в этом режиме не поддерживается.

В базе хранится только SHA-256 случайной ссылки, не сама ссылка. RLS включён, публичных прав нет. Дата и время не принимаются от клиента как подтверждённые. Старые кнопки с другим временем аннулируются. Атомарный переход состояния не допускает повторного подтверждения.

Если сеть оборвалась при отправке и результат неизвестен, запись помечается uncertain и не пересылается автоматически. Нужно связаться с клиентом и проверить результат вручную. Это предотвращает повторное подтверждение без ясности. Если сообщение отправлено, но сохранение статуса прервалось, статус может остаться sending — также нужна ручная проверка. Из лога выводятся только фиксированные коды ошибок, без секретов и данных клиента.

Перед рабочим использованием дополните операторские сведения и политику обработки данных на сайте. Политика уже описывает добровольную привязку Telegram, но юридические реквизиты владельца не предоставлены.

## Проверка включения

Используйте свежую тестовую заявку и по возможности отдельный клиентский Telegram-аккаунт. Убедитесь, что подтверждение получено в правильном аккаунте с правильными услугой, датой, временем и адресом. Повторное нажатие владельцем не должно отправить второе подтверждение. Реальная проверка этого нового сценария пока не выполнена — ключи доступны только владельцу в Netlify, миграция и webhook ещё не активированы.

Локальные автоматические проверки: cd site; npm test; npm run lint; npm run build. Интеграционные тесты подменяют Supabase и Telegram, не отправляют реальные сообщения.
